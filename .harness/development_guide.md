# 🚀 Naver Cafe Auto Manager - 바이브 코딩 가이드 (Vibe Coding Guide)

이 문서는 AI 에이전트나 개발자가 추가 설명 없이 이 지침만 보고 코드를 고치거나 새로 작성(바이브 코딩)해도 에러가 나지 않도록 구현 방식, 구조적 설계, 주의점 및 핵심 API를 상세히 기술한 마스터 가이드라인입니다.

---

## 1. 전역 인코딩 및 환경 규칙
* **UTF-8 강제**: 모든 코드, 주석, 마크다운 문서 및 로그 파일은 반드시 **BOM 없는 UTF-8** 인코딩으로 저장해야 합니다. (ANSI, CP949 절대 금지)
* **터미널 세션**: PowerShell/CMD에서 작동을 수행할 때는 명령어 처두에 반드시 `chcp 65001`을 추가하여 인코딩 유실로 인한 파이프라인 에러를 차단합니다.

---

## 2. 네이버 봇 탐지 우회 및 크롤링 아키텍처
* **Playwright Stealth**: 네이버 카페 접속 및 뉴스 크롤링 시에는 반드시 `playwright_stealth` 플러그인의 `Stealth` 인스턴스를 사용해야 합니다.
  ```python
  from playwright_stealth import Stealth
  stealth = Stealth()
  await stealth.apply_stealth_async(context)
  ```
* **세션 재사용 정책**: 
  - ID/PW 입력은 캡차(CAPTCHA) 및 2차 인증에 의해 상시 차단됩니다.
  - 이를 우회하기 위해 최초 1회 헤드풀 브라우저로 로그인하여 쿠키/스토리지를 `data/session.json`에 영구 보존하고, 이후 백그라운드 구동 시 이 세션을 주입하여 로그인 상태를 유지합니다.
* **모바일 및 FE URL 주소 구조**:
  - 네이버 카페 PC용 iframe 주소는 리다이렉트나 봇 방어막이 두텁습니다.
  - 실시간 스케줄링 감시는 모바일 주소 `https://m.cafe.naver.com/ca-fe/web/cafes/{club_id}/menus/{menu_id}`를 타겟팅합니다.

---

## 3. 신고/건의 게시판 실시간 모니터링 DOM 구조
* **동적 SPA 렌더링**: 모바일 카페 메뉴 페이지는 Vue.js SPA 기반으로 작동하므로 BeautifulSoup으로 정적 HTML 파싱 시 글 목록이 `0`개로 수집됩니다. 반드시 Playwright의 `page.evaluate()`를 통해 브라우저에서 직접 DOM을 읽어야 합니다.
* **DOM 및 데이터 추출 규칙**:
  - 각 게시글 항목: `li.ListItem`
  - 링크 요소: `a.mainLink` (href 형식 예: `/ArticleRead.nhn?clubid=...&articleid=25`)
  - **작성자 및 작성 시간 파싱**: `a.mainLink` 요소의 `innerText`를 줄바꿈(`\n`) 기준으로 split 하여 정제합니다.
    ```javascript
    const lines = linkEl.innerText.trim().split('\n').map(l => l.trim()).filter(Boolean);
    const title = lines[0];    // 제목
    const author = lines[1];   // 작성자 닉네임
    const postedAt = lines[2]; // 작성 시간
    ```
* **작성 시간 가공 포맷 (한국시 KST 기준)**:
  - 당일 작성글 (예: `10:48`) ➡️ `YYYY.MM.DD HH:MM` (예: `2026.07.20 10:48`)로 변환.
  - 이전 작성글 (예: `26.07.19.`) ➡️ `YYYY.MM.DD` (예: `2026.07.19`)로 변환.

## 4. 뉴스 수집 및 중복 방지 (Deduplication) 규칙
* **3중 교차 검증 중복 차단**: 뉴스 포스팅 시 중복 발행을 절대 방지하기 위해 다음 3단계 교차 체크를 필수로 적용해야 합니다.
  1. **기사 고유 ID 검증**: SQLite `news_archives` 테이블의 `article_id` 필드 유니크 체크.
  2. **기사 제목 검증**: 동일 제목(`title` 필드)의 포스팅 유무 체크.
  3. **물리 아카이브 폴더 검증**: DB 리셋 상태에서도 필터가 작동하도록 로컬 `data/archive/{article_id}` 디렉토리 존재 여부 체크.
* **뉴스 요약 및 게시 양식**:
  - 본문 텍스트 타이핑 시 줄바꿈마다 `Enter` 키 스트로크를 주어야 문단 분리가 정상 작동합니다.
  - 출처 URL을 입력할 때는 이모지(`🔗 ` 등)와 주소를 분리하거나 한 줄에 순수 `http://` 또는 `https://` 주소만 단독 타이핑하여 스마트에디터 ONE의 자동 하이퍼링크 카드 렌더링을 트리거해야 합니다.
  - **스마트에디터 ONE 등록 버튼**: 네이버 웹 에디터 내에서 우측 상단 등록 버튼은 `button`이 아닌 `a.BaseButton--skinGreen` 요소를 타겟팅해야 합니다. (여러 유사 클래스가 있을 수 있으므로 `.first` 요소를 지정하여 확실하게 클릭을 트리거해야 함)

## 5. 자동화 등업 규칙 및 닉네임 정합성 조건
* **닉네임 유효성 5대 조건**:
  가입 후 정회원 자동 등업 대상인지 판독할 때 닉네임 유효성을 엄격하게 스캔해야 합니다.
  1. 숫자로만 구성되어 있을 것 (길이 20자리 이하).
  2. 동일 숫자가 연속 5번 이상 반복되지 않을 것.
  3. 무작위 연속 오름차순/내림차순 숫자 조합이 없을 것.
  4. LCK 밈 관련 특정 혐오성 숫자 패턴(`1557`, `88888`)이 포함되지 않을 것.
  5. 닉네임의 구간 반복이 없을 것.
* **활동량 검증 조건**:
  - 가입인사 게시판 작성 여부 체크.
  - 방문 횟수 `3회` 이상, 작성 댓글 수 `5개` 이상.

## 6. DB 설계 및 이벤트 로깅
* **SQLite 파일 경로**: `data/database.sqlite` (절대 `backend/` 내부에 위치시켜선 안 되며, 컨테이너 볼륨 마운트 대상인 `data/`에 위치해야 함)
* **이벤트 로깅 규칙**: `logger.py` 내 `log_event()`를 호출하면 텍스트 파일 로그와 SQLite DB `action_logs` 테이블에 자동 동시 분산 기록됩니다.
  - `status`가 `"SUCCESS"` 또는 `"INFO"`이면 자동으로 `INFO` 등급 로깅.
  - `status`가 `"FAILED"` 또는 `"ERROR"`이면 자동으로 `ERROR` 등급 로깅.
  - **실시간 작업 로그 발송**: 중간 디버그 알림(스팸)을 원천 차단하기 위해 `logger.py` 내의 자동 발송은 배제하며, 대신 자동 가입 승인(`JOIN_APPROVE`), 자동 등업(`LEVEL_UP`), 뉴스 게시(`NEWS_PUBLISH`/`NEWS_POST`)의 **최종 비즈니스 프로세스 완료 시점(성공/실패)에만 딱 1건의 알림**을 `log_webhook_url` 채널로 `notify_action_log` 웹훅을 통해 전송합니다. 실패 시에는 구체적인 오류 원인을 포함시켜 발송해야 합니다.

---

## 7. 디스코드 프리미엄 웹훅 발송 (Rich Embeds)
* Webhook 호출 시 단순 텍스트가 아닌 `embeds` 배열에 상세 JSON을 실어 색상(Crimson Red `0xE74C3C` for 신고 / Cyan Blue `0x3498DB` for 건의 / Emerald Green `0x2ECC71` for 성공 로그 / Alizarin Red `0xE74C3C` for 실패 로그) 및 포맷팅된 필드를 전송합니다.
* **가독성 확보 규칙**:
  - 플레이라이트의 복잡하고 긴 내부 `Call log` 메시지 등을 감지하여 핵심 헤드라인만 축약해서 노출시킵니다.
  - 여러 줄로 된 상세 정보/오류 메시지는 디스코드 마크다운의 인용구(`>`) 대신 **코드 블록(```)**으로 감싸서 레이아웃 손상을 완전히 방지합니다.
* **웹훅 주소의 3개 분기 매핑 규칙**:
  - `report_webhook_url` (신고 알림 전용)
  - `suggestion_webhook_url` (건의 알림 전용)
  - `log_webhook_url` (작업 로그 및 뉴스 미분류 알림 전용)
  - 개별 웹훅 주소가 빈 문자열 `""`인 경우, 하위 호환성을 위해 기본 `webhook_url`을 백업(Fallback) 주소로 사용합니다.
* 모든 디스코드 알림 발송 시 성공 여부는 DB 로그에 기록되어야 합니다.

## 8. 대량 신규 글 유실 방지용 무한 스크롤 자동화 탐색
* **탐색 필요성**: 모바일 네이버 카페 목록은 무한 스크롤(동적 렌더링) 방식으로 동작합니다. 감시 주기 도중 수십 건의 새 글이 밀려 들어오면 1페이지 화면 아래로 오래된 새 글이 밀려 유실됩니다.
* **작동 메커니즘**:
  - 각 게시판을 모니터링할 때 최하단 게시글 ID 마저 `seen_articles`에 없는 완전히 새로운 글인 경우 아래에 감지되지 않은 새 글이 더 존재한다고 판단합니다.
  - 이 경우 Playwright 브라우저 단에서 `window.scrollTo(0, document.body.scrollHeight)` 스크롤 다운을 동적으로 실행하고 2초 대기하여 이전 글 목록을 추가 로드합니다.
  - 이미 읽었던 글이 감지되거나, 스크롤을 해도 글 목록 개수가 늘어나지 않거나, 최대 스크롤 제한 횟수(`max_scrolls = 4`)에 도달할 때까지 루프를 돌며 아래 영역을 확장하여 스캔합니다.
  - 이를 통해 글이 폭증하더라도 누락 없이 100% 감지 및 디스코드 발송을 보장합니다.
