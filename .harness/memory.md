# 🧠 프로젝트 활성 메모리 (Project Active Memory)

## 1. 프로젝트 개요 (Overview)
- **목적**: 네이버 카페 운영진의 반복적인 회원 관리 업무(가입 승인, 등업 심사)를 자동화하고, 최신 LCK e스포츠 뉴스를 규칙에 맞게 가공하여 게시 및 영구 보관하는 통합 에이전트 시스템입니다.
- **주요 기능**:
  - **가입 자동화**: 실시간(1분 주기) 대기자 전체 자동 가입 처리.
  - **스마트 등업**: 닉네임 형식(20자리 연속되지 않은 무작위 숫자), 방문 횟수(3회), 댓글 작성 수(5회), 가입인사 게시판 글 작성 여부를 모두 검증하여 정회원 자동 등업 처리.
  - **뉴스 아카이브 & 게시**: LCK 기사 수집, 팀별 균등 분배(팀당 최대 2개), 인터뷰 가중치 정렬, 원문 대비 50% 미만 분량 요약(무료/AI), 본문 이미지 및 마크다운 원문 로컬 아카이빙 후 카페에 자동 게시.
  - **실시간 디스코드 알림**: 신고 게시판 및 건의 사항 게시판의 새 글 감지 시 즉각 디스코드 웹훅 알림 발송.
  - **프리미엄 관리자 페이지**: 글래스모피즘 기반 다크모드 웹 대시보드로 실시간 세션 로그인, 모니터링 주기 제어, 통합 수동 API 호출, 이벤트 로그 모니터링, 이미지 뷰어 탑재 뉴스 아카이브 제공.

## 2. 기술 스택 및 인프라 (Tech Stack & Infrastructure)
- **백엔드**: Python 3.12 (FastAPI, SQLAlchemy, Playwright + Stealth 플러그인, SQLite)
- **프론트엔드**: Vite + React (Vanilla CSS 기반 변수화 스타일링, Lucide-React)
- **기동 및 감시**: `watchdog.py` 및 `run.bat` 통합 프로세스 관리자
- **사용 포트**:
  - 백엔드 (FastAPI/Production): 8000포트 (대시보드 빌드본 마운트 포함)
  - 프론트엔드 (Vite/Development): 5173포트 (실시간 핫 리로딩 개발용)
- **핵심 파일 구조**:
  - `backend/`: config, database, logger, naver_bot, news_crawler, scheduler, discord_notifier, main 탑재
  - `frontend/src/`: 대시보드, 설정 제어, 로그/아카이브 UI 탑재
  - `data/`: `config.json`(설정), `session.json`(네이버 세션), `database.sqlite`(로그/아카이브 DB), `archive/`(원문+이미지 저장)

## 5. 장기 레퍼런스 및 아키텍처 결정 이력 (Long-Term Reference Index)
- **네이버 카페 URL 중앙 관리 도입**: 개별 스케줄러, 봇, 알림 등의 파일에 하드코딩되어 분산되어 있던 PC/모바일 네이버 카페 URL 주소들을 `backend/config.py`의 전역 링크 빌더 함수(`get_pc_article_url`, `get_mobile_article_url` 등)로 완전 일원화하여 유지 보수성 대폭 상향. (2026-07-20)
- **2026 e스포츠 메타데이터 및 동의어 보완**: 2026년 리브랜딩 및 네이밍 스폰서 변동 팀(한진 브리온, 키움 DRX, DN 숲퍼스)과 신규 공식 3글자 약칭(**DNS** for SOOPers, **KRX** for Kiwoom DRX)을 동의어로 완벽히 바인딩하고, 신설 국제 대회인 '퍼스트 스탠드(First Stand/FST)' 동의어를 통합하여 기사 필터 분류 지능화. (2026-07-20)
- **계층형 TEAM_METADATA 구조 도입**: 동의어 매핑 대상을 `team_names`, `players`(닉네임/본명/실명), `coaches`(닉네임/본명/실명)로 명확히 계층화 및 구조 분리하여 가독성을 높이고, 기사 제목과 본문에서 각 카테고리별로 정교한 정합성 판정이 가능하게 설계 변경. (2026-07-20)
- **모바일 캡처 가이드라인 기반 닉네임 5대 규칙 정합화**: 네이버 카페 공식 가이드라인 이미지에 기재된 닉네임 유효성 5개 규칙(구간 반복 차단, 혐오 숫자 1557/88888 차단, 5자리 이상 연속/동일 숫자 차단)을 `is_random_numeric_nickname` 알고리즘에 완전 이식 및 검증 완료. (2026-07-20)
- **팀 분류 실패 시 디스코드 알림 구현**: 기사 필터링 및 소속 분석 도중 `"일반"` (분류 매칭 실패) 기사가 발생했을 때, 해당 기사의 제목/URL 링크 및 상세 에러 메시지를 디스코드 채널로 실시간 알리는 `notify_team_classification_failure` 웹훅 파이프라인 구축. (2026-07-20)
